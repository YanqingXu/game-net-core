# v0.5.0 Experimental Preview Track

Status: implementation surface prepared; no tag or GitHub Release has been
published by IOE-X15.

The preview track adds one explicit Linux-only package component:

```cmake
find_package(GameNetCore 0.3.0 EXACT REQUIRED
    COMPONENTS experimental_io_uring)
target_link_libraries(my_server PRIVATE GameNet::experimental_io_uring)
```

The package producer enables the component with
`-DGAMENET_ENABLE_EXPERIMENTAL=ON`; the downstream consumer only requests the
installed component shown above.

`GAMENET_ENABLE_EXPERIMENTAL` remains off by default. A package produced
without it does not contain the component, its library, or its headers, and a
component request fails during CMake configuration. Windows continues to
reject the option. Linux production still defaults to epoll and Windows to
IOCP; the installed experimental target does not add a selector or automatic
fallback.

The experimental component API version is `0.1.0`. Its independent inventory
and header fingerprints are recorded in
`api/experimental_io_uring_api_manifest.json`. It is not part of the stable
v0.3 compatibility manifest, and neither source nor ABI compatibility is
promised before a separately approved experimental release.

The installed façade classes are `IoUringTcpServer` and `IoUringTcpClient`.
Their transitive Engine/Pump/Hub/Adapter headers are present because the façade
option, result, and summary types expose that vocabulary. The proof-only
`IoUringTcpConnectionDriver` and `IoUringTcpMultiOwnerServer` headers remain
source-private and are not installed.

Runtime ownership is unchanged: the caller owns and outlives the EventLoop and
façade; all Server/Client lifecycle, observation, callbacks, and destruction
remain on that owner. Only the existing bounded Adapter Send/Shutdown/Force
admission is callable from a foreign thread. Installation makes no performance
or production-backend claim and authorizes no advanced io_uring features.
