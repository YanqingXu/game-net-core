## Scope

This maintenance candidate includes the accepted-output graceful-shutdown fix
already merged in `a4d4af64dcc7ae5fdfb0f39c5cb3cfa0764512b6`.
Previously, a foreign thread could receive `Accepted` from send and shutdown
while the owner loop was paused, then observe EOF before queued output was
sent. Output admission now seals atomically with reservation, graceful
half-close waits for every accepted reservation to settle, and final release
or allocation/post rollback wakes lifecycle progress even if the normal queue
is full. Repeated shutdown does not recreate a completed half-close obligation.
Windows continues reading during the write half-close until peer EOF.

The connection's EventLoop still owns socket/Channel mutation and callbacks.
Accepted send closures retain the connection; foreign threads use atomic
admission and owner dispatch. No ownership, callback-affinity, installed API or
target change is introduced by release preparation. The direct regression is
`tests/contract/tcp_connection/test_tcp_connection_cross_thread_shutdown.cpp`.
See the [original fix validation](../2026-10-13-graceful-drain-validation.md).

The package version becomes 0.3.1 within the existing 0.3 source compatibility
line. Consumers must rebuild; no binary ABI promise is added. Default packages
remain static Core plus provisional foundations; experimental io_uring stays
opt-in. HP0 remains `DEFER`; this release makes no new performance claim.
